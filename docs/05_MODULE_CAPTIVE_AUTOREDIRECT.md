# 05. Module Deep Dive: Captive Autoredirect (Node.js)

Captive Autoredirect runs several local services behind one rogue AP flow:

1. `dnsmasq` gives clients the AP IP as DNS and gateway.
2. `captive-map.service` watches `dnsmasq` queries and records each client IP's requested origin in `captive/captive.db`.
3. `nginx` redirects captive-check and target-domain HTTP traffic to the default captive server on port `3003`.
4. `default-captive/server.js` renders `default-captive/views/connect.ejs` and redirects the client to the local target server that matches the recorded origin.
5. The target server (`facebook`, `instagram`, or `x`) stores the submitted form data and then opens internet access for that client IP.

## Node Servers

`captive/start-server.sh` starts four Express servers:

```bash
facebook        -> 0.0.0.0:3000
instagram       -> 0.0.0.0:3001
x               -> 0.0.0.0:3002
default-captive -> 0.0.0.0:3003
```

## Domain Mapping

`captive/mapping-domain.sh` generates `/usr/local/bin/captive-map.py` and a systemd unit named `captive-map.service`.

The mapper reads these runtime values from environment variables generated by the orchestrator:

```bash
PROJECT_DIR=/path/to/captiveframework/modules/captive-autoredirect
AP_IP=10.99.0.1
```

It writes `/etc/nginx/conf.d/destmap.conf` with the current AP IP each time the service starts, so stale IPs from another machine should not survive a restart.

## Portable Startup

Do not commit or hardcode local interface names. On each machine, select interfaces from the dashboard before starting the module:

- AP interface: WiFi adapter that supports AP/master mode
- Internet interface: upstream internet connection

For manual testing, pass env vars explicitly:

```bash
sudo AP_IFACE=wlan1 INTERNET_IFACE=eth0 AP_IP=10.99.0.1 ./start.sh
```

`start.sh` exits with a clear error if either interface is missing.
